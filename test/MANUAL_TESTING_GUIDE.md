# 🧪 Посібник із ручного тестування системи (Manual Testing Guide)

Цей посібник містить вичерпні інструкції для ручного тестування системи автоматизації звітності кафедри (`ai-bird-secretary`). 

Тестування розділене на **три рівні**:
1. **Рівень 1: Повністю автономне локальне тестування (без ключів Google)** — тестує парсинг файлів, агрегацію, правило `0` для прочерків та Groq AI.
2. **Рівень 2: Симуляція життєвого циклу CLI (Dry-Run)** — тестує аргументи командного рядка (`--monitor`, `--draft`, `--reconcile`, `--final`).
3. **Рівень 3: Живе наскрізне тестування (Live End-to-End)** — тестує підключення до реального Google Classroom, Telegram-бота та надсилання листів на Gmail.

---

## 🚀 Рівень 1: Автономне ручне тестування (Offline)

Цей режим не потребує налаштування облікових записів Google і дозволяє негайно перевірити бізнес-логіку на готових зразках документів з папки `test/docs/`.

### Крок 1.1: Запуск тестового конвеєра на готових документах
Виконайте команду:
```bash
npm run test:manual
```

**Що відбувається та що перевіряти в консолі:**
* ✅ **Парсинг Word/Excel:** завантажуються документи з підпапок `01_Викладач_Іваненко_О_В/`, `02_Професор_Петренко_В_М/`, `03_Доцент_Сидоренко_А_П.../` та `04_Асистент_Ковальчук_.../`.
* ✅ **Перевірка критичного правила прочерків:** перевіряється, що значення `"-"`, `"інформація відсутня"`, `"немає"` та `0` обчислюються як `0`.
* ✅ **Нейромережа Groq AI:** аналізує неструктурований звіт викладача Ковальчука та генерує аналітичне резюме (Executive Summary) для завідувача кафедри.
* ✅ **Збір фотозвітів JPEG:** знайдено 3 файли `.jpeg` (сертифікати Scopus, диплом керівника, фото доповіді), які реєструються для пересилання до наукового відділу.
* ✅ **Генерація фінальної матриці:** формується звіт на 92+ рядки.
* 💾 **Перегляд результату:** у папці `test/docs/PREVIEW_REPORT.txt` генерується текстова копія таблиці для візуального огляду.

### Крок 1.2: Перевірка парсера на граничні випадки (Edge Cases)
```bash
npm run test:parser
```
Перевіряє 53 тести:
- Різні види дефісів (`-`, `–`, `—`, `−`, `―`).
- Дробні числа (`14,8`, `14.8`), пробіли у тисячах (`1 250`, `1 500,75`).
- Відновлення після пошкоджених файлів (биті бінарні буфери Word та Excel не крашать систему).

### Крок 1.3: Перевірка роботи Groq AI
```bash
npm run test:ai
```
Перевіряє зв'язок з Groq API (`qwen/qwen3.8-27b`) та автоматичне перемикання на шаблонний fallback за відсутності мережі/ключа.

## ⏱️ Рівень 2: Симуляція CLI та робочих фаз (Dry-Run)

Система розрахована на запуск через **Windows Task Scheduler** раз на добу або виклик з відповідними прапорцями.

### Крок 2.1: Діагностика середовища (Healthcheck)
```bash
npm run check
# або: npx tsx src/index.ts --healthcheck
```
Виводить статус усіх конфігурацій:
- Наявність `credentials.json` та `token.json`.
- Доступність Telegram-бота (`TELEGRAM_BOT_TOKEN`).
- Валідність змінних `.env`.

### Крок 2.2: Автономна симуляція повного розкладу (--dry-run)
```bash
npm run dry-run
# або: npx tsx src/index.ts --auto --dry-run
```
Симулює весь життєвий цикл без запитів до Google API:
1. Знаходить завдання "Інформація про науково-дослідну роботу".
2. Обчислює дні до дедлайну.
3. Симулює запуск необхідної фази (Т-3, Т-1 або Final).

### Крок 2.3: Ручний запуск конкретних фаз у режимі симуляції

1. **Фаза моніторингу (Monitoring Phase):**
   ```bash
   npx tsx src/index.ts --monitor --dry-run
   ```
2. **Фаза Т-3 Дні (Попередній зведений звіт та нагадування):**
   ```bash
   npx tsx src/index.ts --draft --dry-run
   ```
3. **Фаза Т-1 День (Перерахунок запізнілих здач):**
   ```bash
   npx tsx src/index.ts --reconcile --dry-run
   ```
4. **Фінальна здача (Deadline Day):**
   ```bash
   npx tsx src/index.ts --final --dry-run
   ```

## 🌐 Рівень 3: Живе наскрізне тестування (Live End-to-End)

Для тестування з реальними сервісами Google та Telegram виконайте наступні кроки.

### Крок 3.1: Підготовка змінних оточення (`.env`)
Переконайтеся, що файл `.env` містить реальні значення:
```env
GOOGLE_CREDENTIALS_FILE=credentials.json
GOOGLE_TOKEN_FILE=token.json
CLASSROOM_COURSE_ID=ваш_ідентифікатор_курсу
ASSIGNMENT_NAME="Інформація про науково-дослідну роботу"
TELEGRAM_BOT_TOKEN=ваш_токен_бота
HEAD_OF_DEPT_CHAT_ID=ваш_chat_id_telegram
HEAD_OF_DEPT_EMAIL=head@example.com
SCI_DEPT_EMAIL=s_galina_2005@ukr.net
STATIC_PLAN_SHEET_ID=ід_таблиці_плану_роботи
STATIC_SCI_PLAN_SHEET_ID=ід_таблиці_плану_науки
MASTER_OUTPUT_FOLDER_ID=ід_папки_на_drive
GROQ_API_KEY=ваш_gsk_ключ_groq
```

### Крок 3.2: Авторизація в Google OAuth2
```bash
npm run auth:init
```
1. У терміналі відкриється посилання для авторизації Google.
2. Увійдіть у навчальний Google-акаунт із доступом до Класу та Диску.
3. Вставте код підтвердження або завершіть flow. Файл `token.json` буде створено автоматично.

### Крок 3.3: Створення тестового завдання в Google Classroom
1. Зайдіть у Google Classroom як викладач курсу.
2. Створіть завдання з точною назвою: **`Інформація про науково-дослідну роботу`**.
3. Встановіть кінцевий термін здачі (дедлайн):
   - Для тестування фази **Т-3**: виставте дедлайн через **3 дні** від поточної дати.
   - Для тестування фази **Т-1**: виставте дедлайн на **завтра**.
   - Для тестування **Final**: виставте дедлайн на **сьогодні**.

### Крок 3.4: Завантаження тестових відповідей студентами/викладачами
У папці `test/docs/06_Зразки_для_Google_Classroom_швидке_завантаження/` підготовлено готовий комплект:
1. Зайдіть під тестовими акаунтами викладачів (або додайте файли вручну як відповіді студентів):
   - **Викладач 1:** додайте `Іваненко_Додаток_3_Публікації.docx` та `Іваненко_Сертифікат_Scopus.jpeg`.
   - **Викладач 2:** додайте `Петренко_Додаток_18_Гранти.docx` та `Петренко_Диплом.jpeg`.
   - **Викладач 3:** додайте `Сидоренко_Додаток_3_прочерки_та_нулі.docx`.
   - **Викладач 4:** додайте `Ковальчук_Звіт_для_ШІ.docx`.
   - **Викладач 5:** залиште без здачі (для перевірки списку боржників).
2. Натисніть **«Здати» (Turn in)** у Google Класі.

### Крок 3.5: Запуск живого виконання
Виконайте автоматичний або фазовий запуск:
```bash
# Автоматичний вибір фази за датою дедлайну:
npm start -- --auto

# Або примусовий запуск Т-3:
npm start -- --draft

# Або примусовий фінальний запуск:
npm start -- --final
```

| **4** | **Список боржників (Т-3)** | Telegram та Email завідувача | Надіслано ПІБ викладачів, які не здали звіт, із попередженням про 48 годин. |

## 🛠️ Налаштування розкладу у Windows Task Scheduler

Для щоденного виконання за розкладом о 08:00 ранку:
1. Відкрийте **Планувальник завдань Windows (Task Scheduler)**.
2. Створіть нову задачу:
   - **Trigger:** Щодня о 08:00.
   - **Action:** Запуск програми.
   - **Program/script:** `node` (або `npx`)
   - **Add arguments:** `dist/index.js --auto` (або `tsx src/index.ts --auto`)
   - **Start in:** `C:\Users\vadym\Downloads\ai-bird-secretary`
3. Збережіть задачу. Система щоранку перевірятиме статус дедлайну та надсилатиме звіти.
